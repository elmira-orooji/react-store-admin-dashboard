# وایرفریم صفحه ورود

## هدف صفحه

کاربر باید بتواند با کمترین حواس‌پرتی وارد پنل شود. در این مرحله تمرکز روی ترتیب محتوا و رفتار فرم است و رنگ و هویت بصری نهایی نیست.

## چیدمان دسکتاپ

صفحه به دو بخش تقسیم می‌شود:

- بخش معرفی کوتاه محصول
- فرم ورود

فرم در یک محدوده جمع‌وجور قرار می‌گیرد و شامل عنوان، توضیح کوتاه، ایمیل، رمز عبور و دکمه ورود است. بخش معرفی فضای بیشتری دارد، اما محتوای آن کوتاه می‌ماند تا توجه از فرم گرفته نشود.

## چیدمان موبایل

- بخش معرفی حذف می‌شود.
- نام محصول بالای فرم قرار می‌گیرد.
- فرم تمام عرض قابل استفاده را می‌گیرد.
- فاصله کنترل‌ها برای لمس راحت حفظ می‌شود.

## ترتیب محتوا

1. نام محصول
2. عنوان «ورود به پنل مدیریت»
3. توضیح کوتاه
4. فیلد ایمیل
5. فیلد رمز عبور و کنترل نمایش رمز
6. پیام خطای عمومی در صورت نیاز
7. دکمه ورود

## متن‌های رابط

| بخش | متن |
|---|---|
| عنوان | ورود به پنل مدیریت |
| توضیح | برای ادامه، ایمیل و رمز عبور خود را وارد کنید. |
| برچسب ایمیل | ایمیل |
| نمونه ایمیل | name@example.com |
| برچسب رمز | رمز عبور |
| اقدام اصلی | ورود به پنل |
| ایمیل خالی | ایمیل را وارد کنید. |
| ایمیل نامعتبر | فرمت ایمیل درست نیست. |
| رمز خالی | رمز عبور را وارد کنید. |
| خطای ورود | ایمیل یا رمز عبور درست نیست. دوباره تلاش کنید. |
| خطای شبکه | ارتباط با سرور برقرار نشد. دوباره تلاش کنید. |

## رفتار فرم

- خطای هر فیلد بعد از خروج از فیلد یا ارسال فرم نمایش داده می‌شود.
- پیام خطا زیر همان فیلد قرار می‌گیرد.
- پس از ارسال ناموفق، focus به اولین فیلد دارای خطا می‌رود.
- دکمه نمایش رمز، مقدار فیلد را تغییر نمی‌دهد.
- هنگام ارسال، متن دکمه به «در حال ورود…» تغییر می‌کند و ارسال دوباره غیرفعال می‌شود.
- پیام خطای سرور بالای دکمه نمایش داده می‌شود.
- اطلاعات ایمیل پس از خطای سرور باقی می‌ماند.

## دسترس‌پذیری

- برچسب‌ها همیشه نمایش داده می‌شوند و placeholder جای برچسب را نمی‌گیرد.
- پیام خطا به فیلد مربوط متصل می‌شود.
- کنترل نمایش رمز نام قابل‌فهم دارد.
- ترتیب حرکت با Tab مطابق ترتیب بصری است.
- وضعیت focus واضح باقی می‌ماند.

## معیار پذیرش

- فرم در عرض ۳۲۰ پیکسل اسکرول افقی ندارد.
- همه کنترل‌ها با صفحه‌کلید قابل استفاده‌اند.
- کاربر دلیل خطا و روش اصلاح آن را متوجه می‌شود.
- در هر لحظه فقط یک اقدام اصلی دیده می‌شود.
- وضعیت عادی، خطا و در حال ارسال طراحی شده‌اند.

## نکته برای طراحی نهایی

بعد از مشخص‌شدن هویت بصری، رنگ اصلی، تایپوگرافی و تصویر بخش معرفی تعیین می‌شوند. ساختار فرم بدون دلیل مشخص تغییر نمی‌کند.
