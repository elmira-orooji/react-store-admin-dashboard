# هویت بصری و Design System اولیه

## ۱. شخصیت محصول

نام موقت محصول «ویترینو» است. این نام تا پیش از تست با کاربر و بررسی نام تجاری قطعی نیست، اما برای یکدست‌شدن طراحی و متن‌های رابط استفاده می‌شود.

ویترینو باید این ویژگی‌ها را منتقل کند:

- روشن و قابل‌فهم
- قابل اعتماد
- منظم، بدون حس خشک و اداری
- مناسب استفاده روزانه

رابط نباید بیش‌ازحد تزئینی باشد. اطلاعات فروشگاه و اقدام‌های کاربر باید بیشتر از عناصر برند دیده شوند.

## ۲. لحن نوشتاری

متن‌های رابط کوتاه، مستقیم و محترمانه‌اند.

### اصول

- از فعل‌های مشخص استفاده می‌کنیم: «ذخیره محصول»، «تغییر وضعیت»، «پاک‌کردن فیلترها».
- پیام خطا فقط مشکل را نمی‌گوید؛ روش اصلاح را هم مشخص می‌کند.
- برای عملیات عادی از لحن رسمی و سنگین استفاده نمی‌کنیم.
- اصطلاح انگلیسی فقط زمانی استفاده می‌شود که معادل فارسی آن نامأنوس باشد.

### نمونه

مناسب: «قیمت باید بیشتر از صفر باشد.»

نامناسب: «مقدار واردشده نامعتبر است.»

مناسب: «تغییرات ذخیره شد.»

نامناسب: «عملیات با موفقیت انجام پذیرفت.»

## ۳. رنگ

### رنگ اصلی

بنفش متمایل به آبی برای اقدام اصلی، لینک مهم و focus انتخاب شده است. این رنگ در فضای مدیریتی جدی می‌ماند، اما از خاکستری کامل صمیمی‌تر است.

- Primary 600: `#5B4FE9`
- Primary 700: `#493DCE`
- Primary 100: `#E8E6FF`

### رنگ‌های خنثی

- متن اصلی: `#202124`
- متن ثانویه: `#62666D`
- پس‌زمینه صفحه: `#F6F7F9`
- سطح اصلی: `#FFFFFF`
- خط جداکننده: `#DDE0E5`

### رنگ‌های معنایی

- موفقیت: `#237A4B`
- هشدار: `#A35C00`
- خطا: `#B42318`
- اطلاع‌رسانی: `#2864B8`

رنگ‌های معنایی برای متن و آیکن همراه استفاده می‌شوند. معنی هیچ وضعیت فقط به رنگ وابسته نیست.

## ۴. تایپوگرافی

فونت پیشنهادی «Vazirmatn» است. خوانایی مناسبی در متن فارسی و اعداد دارد و وزن‌های موردنیاز رابط را پوشش می‌دهد.

وزن‌ها:

- ۴۰۰ برای متن و توضیحات
- ۵۰۰ برای عنوان، برچسب مهم و دکمه
- ۷۰۰ فقط برای عددهای کلیدی داشبورد، در صورت نیاز

مقیاس پایه:

| نقش | اندازه | ارتفاع خط |
|---|---:|---:|
| عنوان صفحه | ۲۴px | ۳۶px |
| عنوان بخش | ۱۸px | ۲۸px |
| عنوان کوچک | ۱۶px | ۲۴px |
| متن اصلی | ۱۴px | ۲۲px |
| متن کمکی | ۱۲px | ۲۰px |

اندازه کمتر از ۱۲ پیکسل در رابط استفاده نمی‌شود.

## ۵. فاصله‌گذاری

مقیاس فاصله بر پایه ۴ پیکسل است:

`4, 8, 12, 16, 24, 32, 40, 48`

کاربردهای اصلی:

- فاصله آیکن و متن: ۸px
- فاصله فیلدهای مرتبط: ۱۶px
- padding کارت: ۱۶ یا ۲۴px
- فاصله بخش‌های صفحه: ۲۴px
- padding افقی صفحه دسکتاپ: ۳۲px
- padding افقی صفحه موبایل: ۱۶px

## ۶. گوشه‌ها و سایه

- کنترل کوچک و دکمه: ۸px
- کارت و پنل: ۱۲px
- دیالوگ: ۱۶px
- badge وضعیت: کاملاً گرد

سایه فقط برای دیالوگ، منوی بازشونده و سطحی که روی محتوای دیگر قرار می‌گیرد استفاده می‌شود. کارت‌های عادی با خط مرزی از پس‌زمینه جدا می‌شوند.

## ۷. آیکن

آیکن‌ها خطی و ساده‌اند. اندازه پیش‌فرض ۲۰ پیکسل و ضخامت خط یکدست است.

قواعد:

- در ناوبری، آیکن همراه متن است.
- دکمه آیکن‌تنها باید نام دسترس‌پذیر داشته باشد.
- برای عملیات حساس از آیکن به‌تنهایی استفاده نمی‌شود.
- آیکن تزئینی برای صفحه‌های خالی محدود و ساده است.

## ۸. اجزای پایه

### دکمه

- Primary: اقدام اصلی هر بخش
- Secondary: اقدام مهم با تأکید کمتر
- Ghost: اقدام کم‌اهمیت مانند پاک‌کردن فیلتر
- Destructive: حذف یا خروج بدون ذخیره

در یک محدوده کوچک، بیش از یک دکمه Primary قرار نمی‌گیرد.

### فیلد

حالت‌ها:

- Default
- Hover
- Focus
- Filled
- Disabled
- Error

برچسب همیشه بالای فیلد دیده می‌شود. placeholder فقط مثال یا راهنماست.

### Badge وضعیت

Badge شامل متن و رنگ پس‌زمینه ملایم است. متن وضعیت حذف نمی‌شود.

### کارت

کارت برای گروه اطلاعات مستقل استفاده می‌شود، نه برای هر ردیف یا متن. کارت‌ها سطح سفید، خط مرزی و گوشه ۱۲ پیکسل دارند.

### جدول

- عنوان ستون وزن ۵۰۰ دارد.
- ردیف‌ها فقط خط افقی دارند.
- عملیات در ستون آخر قرار می‌گیرند.
- ردیف hover برای کمک به دنبال‌کردن اطلاعات استفاده می‌شود.
- جدول در موبایل به کارت یا فهرست تبدیل می‌شود.

## ۹. Focus و دسترس‌پذیری

- focus با حلقه ۲ پیکسلی Primary و فاصله ۲ پیکسل نمایش داده می‌شود.
- کنتراست متن اصلی حداقل معیار AA را هدف می‌گیرد.
- متن کمکی روی سطح سفید روشن‌تر از Neutral 600 نمی‌شود.
- ارتفاع هدف لمسی کنترل‌های اصلی حداقل ۴۴ پیکسل است.
- انیمیشن‌ها کوتاه‌اند و با تنظیم کاهش حرکت غیرفعال می‌شوند.

## ۱۰. حالت تاریک

حالت تاریک در MVP ضروری نیست، اما توکن‌های اولیه آن تعریف می‌شوند تا ساختار رنگ به مقادیر ثابت وابسته نشود. ابتدا کیفیت حالت روشن کامل می‌شود و سپس حالت تاریک بررسی خواهد شد.

## ۱۱. موارد نیازمند بررسی

- نهایی‌کردن نام ویترینو
- طراحی نشان یا لوگوتایپ
- تست کنتراست تمام حالت‌های badge
- بررسی فونت روی دستگاه‌های ضعیف و اینترنت کند
- تست اندازه جدول و فرم با داده واقعی
- تصمیم درباره نمایش اعداد فارسی یا لاتین در داده‌های مالی

## خروجی مرحله بعد

در مرحله بعد، اجزای اصلی مانند Button، Input، Select، Badge و Card با حالت‌های دقیق طراحی می‌شوند و سپس یک صفحه وایرفریم به UI نهایی تبدیل می‌شود.
